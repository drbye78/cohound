# Карта страниц PDF на реальном корпусе (O36 фаза 1a)

**Дата:** 15.11.2026
**Срез дерева:** `80a20cd` (плюс доковый проход по якорям)
**Прибор:** `scripts/check_pdf_page_map.py` (named instrument, A3)
**Предмет:** `ExtractedDoc.page_map` читателя `text_layer` (`pdfium-text-4`)

## Вопрос

Можно ли верить `page_map` — покрывают ли её сегменты ровно тот текст, который
опубликован в `doc.text`, без дыр, пересечений и выходов за границу? Фикстура проверяет
форму; корпус — что форма держится на настоящих документах.

## Условия

- Корень: `~/.cohound/data/corpus_raw` (retained-файлы стенда, 12 GB, 44 923 `.bin`).
- Отбор: магия байтов `%PDF-` в смещении 0 (retained-файл суффикса не несёт).
- Механизм: `PdfiumDocumentExtractor.extract_path`, то есть тот же путь, которым идёт
  прогон, без сети и без кэша (кэш обходится намеренно: проверяется читатель).

```
.venv/bin/python scripts/check_pdf_page_map.py
```

## Результат

```
файлов: 307, с текстом: 295, страниц: 21636 (max 2763), max символов: 6514618,
карты нет при тексте: 0, дефектов: 0, 47.9 c
```

- **307 PDF / 21 636 страниц**, крупнейший документ — 2 763 страницы, 6 514 618 символов
  (тот же хвост, что в `2026-11-09-pdf-corpus-profile.md`).
- Дефектов **0**: сегменты отсортированы, не пересекаются, `0 <= start <= end <= len(text)`,
  между соседними сегментами только `""` или `"\n\n"`, обратная сборка
  `"\n\n".join(text[s:e])` равна `doc.text` (до краевого `.strip()`).
- `page_map is None` при непустом тексте — **ни разу**: посегментная финализация не
  разошлась со склейкой ни на одном документе корпуса, включая 2 763-страничный.
- 12 файлов без текста (`doc.text == ""`) — это PDF без текстового слоя целиком, у них
  `error="no_text_layer"` и карты нет по построению (не дефект).

## Текст и хеш не изменились

Сверка с поведением **до** правки: модуль `HEAD` (`git show HEAD:core/adapters/
extract_pdf_text.py`) загружен отдельным модулем, оба читателя прогнаны на тех же 307
файлах.

```
text_diff: 0, hash_diff: 0, err: 0
```

## Цена

Посегментная финализация — один дополнительный проход `finalize_extracted_text`
(10 извлечений × 3 круга, медиана, `head` против нового кода):

| документ | было | стало | Δ |
|---|---|---|---|
| 7 стр. / 15 869 симв. | 28.00 мс | 28.79 мс | **+0.79 мс (+2.8 %)** |
| 9 стр. / 21 536 симв. | 27.31 мс | 28.98 мс | **+1.67 мс (+6.1 %)** |
| 12 стр. / 14 624 симв. | 25.33 мс | 26.35 мс | **+1.02 мс (+4.0 %)** |

Посегментная финализация того же текста стоит столько же, сколько целая
(0.839 против 0.840 мс на 14 624 симв.) — то есть цена линейна по тексту, а не по числу
страниц.

## Что этим не измерено

- **docling** (`structured`) карту не отдаёт — фаза 1b, отдельным решением.
- **`deploy_profile: split`** карту не несёт: шов передаёт только
  `text.content/hash/extractor_version/page_count/partial`, поэтому в ядре `page_map`
  остаётся `None`. Это граница шва (схема `SEAM "1"`), а не дефект читателя.
- Корпус — **модельный профиль** (`ru-pg-dbms`): 307 PDF из 1 721 документа профиля
  (остальные — HTML/Office), числа с него — ориентир, не норма для других профилей.
