**Вход:** сохранённая БД прогона
`~/.cohound/stands/ru-pg-dbms/runs/ru-pg-dbms-145ad66ca3f9/cohound.db` (только чтение,
`mode=ro`). **Токенизатор:** `BAAI/bge-m3`, локальный кэш (`local_files_only=True`), сеть

## Команда

```bash
.venv/bin/python scripts/measure_chunk_token_limit.py \
  --db ~/.cohound/stands/ru-pg-dbms/runs/ru-pg-dbms-145ad66ca3f9/cohound.db \
```

ограничитель работает поверх нарезки и его единица — чанк. «После» отличается от «до»

**Число 04.11 воспроизведено.** Опубликованные 39.888 % чанков plain-text длиннее 512
токенов (`2026-11-04-text-chunker-exact-slices.md:49`) — это **1 128** чанков; здесь тот
же корпус даёт **1 126** (39.816 %). Разница ровно в конвенции: прежний замер считал

**содержимого** — иначе два счётчика одной величины расходились бы на постоянную добавку.
Величина расхождения мала и названа: 2 чанка из 1 128 (0.18 %) стояли на границе 511/512.

## Счётчики ограничителя

| | значение |
|---|---|
| разрезано чанков (`split_chunks`) | **9 567** |
| приклеено хвостов (`absorbed_tails`) | **4 274** |
| без точного среза (`unsplittable`) | **0** |
| кусков > лимита после (`over_limit`) | **4 274** |
| max токенов после | **575** |

`over_limit == absorbed_tails` — не совпадение: приклеивается только хвост короче
`MIN_TAIL_TOKENS = 64` токенов, а кусок перед ним по построению близок к 512, поэтому
склейка всегда выводит за бюджет. Перебор ограничен сверху порогом: **575 − 512 = 63**
токена, то есть меньше объявленных 64. Кусков сверх лимита, не являющихся приклеенным
хвостом, **ноль** — это и есть смысл двух чисел рядом.

## Инварианты (цель — 0)

| | значение |
|---|---|
| **P1** — склейка текстов кусков ≠ склейка входа | **0** документов |
| **точный срез** — `text` ≠ срез `[char_start:char_end]` | **0** кусков |

P1 держится потому, что ограничитель режет, а не переписывает: разделитель между кусками
остаётся в предыдущем куске, `char_start`/`char_end` пересчитываются от родителя. Проверка
независимая: текст «до» и «после» склеивается отдельно и сравнивается, а срез сверяется с
документом, собранным из чанков «до».

## Что это меняет в контракте

Ограничитель **не объявлен**: `TOKEN_LIMIT = None` в `core/adapters/chunker_family.py`,
поэтому `chunker_version` и `chunking_spec` — прежние байт-в-байт, а корпус не меняется
(проверено тестом `tests/adapters/test_chunker_family.py::test_disabled_limiter_keeps_chunks_and_spec_identical`).
Числа выше — цена **включения** условия, а не его текущее действие.

Объявление лимита — `execution_change`: другой состав чанков, `index_build_id` и `run_id`,
полный пере-эмбеддинг (измерено ранее: ~2 ч fp16 на этот корпус, `2026-11-06-embedding-precision-cpu.md`).

### Цена строгого лимита (арифметика из тех же срезов, не отдельный прогон)

Если снять приклейку хвоста (`min_tail_tokens = 0`), позиции резов **не меняются** —
меняется только то, приклеен ли остаток. Значит: чанков станет 262 876 + 4 274 =
**267 150** (+1.63 % к варианту с приклейкой), кусков сверх лимита — **0**, max — 512,
а все 4 274 хвоста пополнят класс «< 64 токенов» (markdown 43 329 → 47 603, доля
17.30 % → 18.34 %). Это не замер, а точный пересчёт по тем же срезам; отдельного прогона
не делалось.

## Чего прибор не измеряет

Качество ретривала, κ оценщика, стоимость эмбеддинга, влияние на промпт. Для первых двух
нужен retrieval-golden (O14), который ждёт разметки D5; здесь — только геометрия в
информационных единицах и её инварианты.

**Не сделано и названо:** объединение **маленьких** чанков (вторая половина формулировки
O21) не реализовано. Основание — число, а не «потом»: 43 427 чанков короче 64 токенов
(markdown 43 329 + text 98) несут 1.991 % токенов корпуса, и объединять их можно только
внутри секции (`heading_path` — часть контракта чанка), то есть сосед обязателен. Замер
`/tmp/opencode/tiny_neighbours.py` (вне репозитория; один проход по `corpus_chunks`,
предфильтр `len(text) < 300`, токены считаются только для кандидатов):

| | значение |
|---|---|
| покрыто предфильтром | **42 887** из 43 427 (98.8 %) |
| секций (документ × `heading_path`) | 131 127 |
| стоят **одни** в своей секции | **37 587** (**87.6 %**) |
| есть сосед с тем же `heading_path` | **5 300** (12.4 %) |

То есть объединять без смены `heading_path` можно 12.4 % класса, и даже там объединение
меняет `text`/`content_hash`/`chunk_no` — то есть состав корпуса (`execution_change`).
Строка «слишком маленькие объединяются» из формулировки O21 на этом корпусе достижима лишь
на восьмой части класса; поэтому механизм не построен, а цена названа. Исключённые
предфильтром 540 чанков — те, где токенов на символ мало (CJK, плотный код); их разбор
не меняет порядок величины.
