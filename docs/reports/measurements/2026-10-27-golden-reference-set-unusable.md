# Golden-набор есть, но проверить им нечего: замер эталона `ru-pg-dbms`

**Дата:** 2026-10-27
**Прогон:** `ru-pg-dbms-3edf2b06097c` (единственный, дошедший до `report`)
**Вопрос:** может ли текущий `packages/ru-pg-dbms/golden.csv` служить эталоном — то есть
отличить верный вердикт от неверного?

## Ответ: нет. И причина не в оценщике, а в составе набора

`hound golden --tier full` по живому прогону:

```
ok: False
agreement: 6.8%              (16 из 236)
total: 236
missing: 217                 (postgrespro 99, pangolin 118)
false_ok: 3
critical_false_absence: 0
violations:
  - R6: golden agreement 6.8% < порога 80.0%
  - R6/§11.1: false ✅ = 3 > 0 (любой false ✅ недопустим)
```

`missing: 217` — это строки эталона, против которых **в прогоне нет ячейки вообще**.
Не «оценщик ошибся», а «сравнивать не с чем». Знаменатель согласия поэтому почти пуст:
16 сравнений на 236 объявленных.

## Почему так: эталон размечен не на тех продуктах

Состав `golden.csv` (перепись строк):

| продукт | строк в golden | корпус в прогоне | ячеек в прогоне |
|---|---|---|---|
| `postgrespro` | 118 | нет | 19 (все из `baselines.csv`) |
| `pangolin` | 118 | нет | 119, все `failed` (`coverage_missing`) |
| `jatoba` | **0** | **есть** (56 док / 9398 чанков) | 119 (32 ✅ / 24 ⚠️ / 63 ❓) |
| `tantor` | **0** | нет | 19 (из `baselines.csv`) |

Эталон размечен на двух продуктах, у которых **корпуса нет**, и не содержит ни одной строки
для единственного продукта, у которого корпус есть. Отсюда 6.8 %: сравниваются только 19
ячеек `postgrespro`, полученных наследованием из `baselines.csv`, — то есть проверяется
механизм наследования, а не оценщик.

## Второй дефект: tier `fast` пуст

Все 236 строк имеют `tier=full`, строк `tier=fast` — ноль. `--tier fast` (PR-гейт, §11.6)
выбирал пустой набор, и тот уходил в `evaluate_golden`:

```
ok: False | total: 0 | agreement: 0.0
violations: ['R6: golden agreement 0.0% < порога 80.0%',
             'R12/§4.2: golden-набор не содержит страты ожидаемых ❌']
```

То есть отчёт о «качестве» там, где фильтр не выбрал ни одной строки. Провалом это было
честным (не молчаливо зелёным), но диагноз вводил в заблуждение. Починено: пустой отбор
теперь `EXIT_USAGE` с `error: golden_tier_empty` и перечнем доступных tier'ов
(`core/cli/commands/golden.py`). «Несравнение» перестало выглядеть как «несогласие».

## Три реальных несогласия — их надо разобрать руками, не пере-прогоном

| продукт | параметр | эталон | прогон |
|---|---|---|---|
| `postgrespro` | `a1_architecture__jit_kompilyaciya_celyh_operatorov` | ⚠️ | ✅ |
| `postgrespro` | `a4_migration__linked_servers_raspredelennye_zaprosy` | ⚠️ | ✅ |
| `postgrespro` | `a1_architecture__izmeneniya_sistemnogo_kataloga` | **❌** | **✅** |

Третья строка — самая опасная по направлению: эталон говорит «вендор этого не заявляет»,
прогон публикует «заявлено». Это false ✅ на параметре, ожидающем отсутствия, то есть
приписывание продукту возможности, которой у него, по эталону, нет. Такое не лечится
повтором: либо эталон устарел, либо вердикт пришёл из наследования (`baselines.csv`) там,
где наследование неприменимо. Решать человеком, с цитатой.

## Что это значит для версионных границ

`execution_change` и `methodology_change` требуют `golden-full` (§13). Сегодня это
требование **невыполнимо этим файлом**: он не покрывает измеряемую популяцию. То есть
формально «golden есть» (236 строк), фактически — «эталона нет». Пока это так, любой
разговор «стало ли лучше» опирается на сравнение прогона с самим собой.

## Что делать (в порядке ценности)

1. **Разметить `jatoba`** — 119 параметров, тот единственный продукт, где есть корпус.
   Без этого эталон не проверяет оценщика вообще.
2. **Присвоить `tier=fast`** документированному подмножеству (дешёвый PR-гейт). Сейчас
   фильтр неисполним; правило отбора — решение владельца, не механика.
3. **Разобрать 3 несогласия** поимённо, с цитатой: устарел эталон или неверен вердикт.
4. Только после этого `golden-full` станет проверкой, а не формальностью.

## Воспроизведение

```bash
.venv/bin/python -m core.cli golden \
  --db runs/ru-pg-dbms-3edf2b06097c/cohound.db \
  --run-id ru-pg-dbms-3edf2b06097c \
  --golden packages/ru-pg-dbms/golden.csv --json
```
