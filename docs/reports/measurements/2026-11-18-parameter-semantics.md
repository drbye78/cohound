## 2. Что размечено

По каждому из 181 параметров:

- `semantics` — что параметр спрашивает на языке предметной области;
- `rule` — правило зачёта: что считается `✅`, что `⚠️`, что `❌` и что **не**
  засчитывается. Уходит в промпт оценщика слотом `RULE` (`core/pipeline/prompt.py:381`);
- `evidence` — где факт доказуем (документ вендора, представление каталога, реестр);
- `absence_rule` — чем доказуем `❌` (I2b/I2c/I2d);
- `terms_ru` / `terms_en` — термины ретривала; второй потребитель — `render_queries`
  (`core/pipeline/prompt.py:402`), три запроса на ячейку;
- `confidence` и `question` — что подтвердить человеку.

## 3. Цена честного класса отсутствия — измерена, не оценена

`explicit` доказуем цитатой прямого отрицания вендора и подписи не требует.
`parameter_reference` и `distribution_absence` публикуются как `❌` **только** при
`bounded`, то есть при `scope_acceptance` (подпись человека на риск) и датированном
носителе (I2d). Числа ниже печатает сам прибор из `golden.csv` (905 строк):

```
❌ всего 282: 275 требуют scope_acceptance
   (distribution_absence 245, parameter_reference 30),
   registry_absence 7 — по реестру, подписи не требуют
```

То есть до подписания **275 из 282 `❌`** становятся `❓` (`not_stated`) — по I2c/I2d,
не по решению прибора. Это не регресс карты: карта перестаёт утверждать то, чего не
измеряла. Раньше эти `❌` держались на константе генератора, а не на отрицании вендора.

Альтернатива — оставить `explicit` — означала бы, что каждый `❌` якобы опирается на
прямое отрицание, которого в корпусе нет. Это ровно тот класс дефекта, который I2c
называет `absence_coverage_unsatisfied`, только тише: он не виден ни в отчёте, ни в
манифесте.

## 4. Что прибор отказывается делать

- **Не переписывает `catalog.csv` молча.** `apply` требует `--out` и собирает файл только
  из записей с заполненным `review`; меняются `rule`/`absence_rule`/`concept_terms`,
  остальные колонки берутся из текущего каталога как есть. Правка каталога —
  `execution_change` (`catalog_digest` входит в `run_id`), и это решение человека.
- **Не принимает правку без пометки.** `compile` отказывает на строке, изменённой без
  `review=fix`: иначе правка человека теряется либо проходит без его решения.
- **Не требует `✅`/`❌` от параметра-значения.** «Разработчик», «Поддерживаемые ОС» и
  ещё пять параметров отвечают величиной, а не «да/нет»; правило обязано назвать
  значение и границы зачёта, а не края шкалы.
- **Не считает повтором термин, стоящий в обоих языках.** `DBaaS` — один термин для
  русского и английского запроса.

константой; `compile` отказывает на правке без `fix`; `apply` не трогает состав пакета.
