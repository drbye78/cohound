# Подложка `state.db`: что проход без сети называет «версии нет» — и чего там нет

**Дата:** 23.11.2026, 13:33 UTC (снимок). **Вход:** `state.db` стенда
(`~/.cohound/stands/ru-pg-dbms/state/ru-pg-dbms/state.db`, 37 760 строк `url_state`),
пакет `packages/ru-pg-dbms` (корни `sources/corpus_urls.yaml`, поддомены
`domain_profiles.yaml`, подачи `sources/manual_artifacts.yaml`).
**Прибор:** `scripts/measure_substrate_reuse.py` (8 тестов, 10 с на 37 760 URL; сеть,
LLM и GPU не нужны).

**Зачем.** A/B оценщика (`2026-11-23-evaluator-ab-v6-v7.md`) не сошёлся не из-за промпта:
корпус в плечах различался. Владелец выбрал «сначала починить подложку». Этот отчёт
отвечает на вопрос, **что именно** в подложке не так, — и ответ оказался не «мало
материала», а «проход без сети возвращает в корпус то, что пакет из него вывел».

## 1. Одно сообщение на четыре разных факта

Прогон `ru-pg-dbms-902c0b71c419` (`--refresh offline`) напечатал **1 590** строк:

```
error: {product}/{url}: offline: переиспользовать нечего — у URL нет активной версии
       документа; документ не вошёл в корпус (сеть не трогается)
```

Прибор классифицировал **те же 1 585 URL** по первичным таблицам (не по журналу: журнал —
не артефакт подложки, у следующего прогона он другой):

| класс | URL | что это на самом деле |
|---|---|---|
| `refused` | **811** | причина записана наблюдением: `robots_disallow` — граница сайта (0.6.0), `source_unavailable`, `not_found`, `payload_too_large`, `parser_failed` |
| `outside_space` | **755** | URL вне **объявленного** пространства продукта: корень выведен из пакета (741 из них — `edu.postgrespro.ru`, выведен 14.11.2026) |
| `provided` | **17** | объявленная подача `jatoba`: байты предъявляются позже в том же прогоне |
| `container` | **1** | архив: у контейнера версии документа нет по построению |
| `has_version` | **1** | версия появилась позже (подложка живёт) |
| `pointer_missing` / `no_version` | **0** | **недостачи подложки среди этих URL нет ни одной** |

То есть сообщение «документ не вошёл в корпус» было ложным в 1 585 случаях из 1 585: ни
один из них не был документом, который лежал в подложке и не переиспользовался.

## 2. Корпусная цена: 302 документа, которых пакет не объявлял

Тот же предикат (`Frontier.scope_admission`: объявленный host + path-prefix по границе
сегмента), применённый к корпусу обоих плеч A/B:

| прогон | документов | вне объявленного пространства |
|---|---|---|
| `ru-pg-dbms-b9b53eb63a53` (v6) | 17 701 | **1** |
| `ru-pg-dbms-902c0b71c419` (v7) | 23 827 | **302** |

Разбор 302:

| продукт | документов вне пространства | что это |
|---|---|---|
| `postgrespro` | **163** | `edu.postgrespro.ru` — корень выведен 14.11.2026 (`c70cdb2`): «2 939 документов / 87 803 чанка = 34,7 % при 0 ячеек на его свидетельстве» |
| `pangolin` | **137** | **другие версии** дерева документации: 6.4.0–6.7.0, 7.1.0, 8.3.0 при объявленном префиксе `/docs/public/PSQ/8.1.0/` |
| `gaussdb` | 1 | — |

Прирост `postgrespro` в плече B равен **163 документам** — ровно выведенному корню. То есть
вся разница корпуса этого продукта между плечами объясняется одним дефектом, а не
изменением сайта.

**Механизм.** Под сетью URL вне scope отсекает `Frontier` — он вызывается на каждом seed.
Под политикой без сети (`offline`/`frozen`) BFS не бывает вовсе, поэтому единственный
источник — `url_state`, и `Frontier` в этом пути **не вызывался**. Строка `url_state` живёт
вечно, а корень можно вывести из пакета — значит выведенный материал возвращался в корпус
молча. Это же объясняет, почему `pangolin` получил 18 версий документации, между которыми
префикс корня специально выбирался, «чтобы бюджет корня не делился и не платили за
дубликаты».

## 3. Что исправлено

1. **Фильтр объявленного пространства в проходе без сети**
   (`plan_incremental_items`, `core/pipeline/corpus_ingest.py`): при `no_network` набор
   известных URL фильтруется тем же предикатом, что у краула
   (`Frontier.scope_admission`), а отброшенные публикуются числом и топ-5 хостов
   (`corpus: … известных URL вне объявленного пространства N (…)`), а не молча.
   Под сетью фильтр не применяется — там пространство держит `Frontier` (тест
   `test_declared_space_filter_is_noop_for_network_policies`).
2. **Три ожидаемых отсутствия версии перестали быть недостачей**
   (`OfflineReuseReport`): `containers` (не документ: члены — по своим URL), `provided`
   (войдут позже в этом прогоне), `refused` (счётчик по виду записанного отказа). Строка
   продукта называет их отдельно, `no_version` остаётся только за настоящим пробелом.
3. Тесты: `tests/pipeline/test_corpus_offline.py` (+4: отказ, контейнер, подача, строка
   отчёта), `tests/pipeline/test_incremental_items_modes.py` (+2: фильтр пространства),
   `tests/scripts/test_measure_substrate_reuse.py` (8).

## 4. Что осталось дефектом подложки

Классы, которые прибор называет честно и которые правкой кода не лечатся:

| продукт | `no_version` (снимок 13:33 UTC) | пример |
|---|---|---|
| `postgrespro` | 878 | `http://postgrespro.ru/about` |
| `pangolin` | 113 | `https://pangolin.sbertech.ru/center/docs/6/about/advantages` |
| `tantor` | 18 | `http://tantorlabs.ru/news` |

Это URL, у которых нет ни версии, ни записанной причины, — то есть документ, который
когда-то наблюдался, но чьих байтов и текста подложка не сохранила. Часть — `http://`
варианты объявленных `https://` адресов. Их лечение — либо живой проход, который их
перечитает, либо явное решение, что они вне пространства. **Ни один из них не входит в
1 585 строк разобранного прогона** — они появились позже.

## 5. Границы

- **Снимок, а не состояние.** `state.db` пишется живым прогоном: два запуска прибора с
  разницей 3 минуты дали `pangolin` `no_version` 94 и 113, а `url_state` вырос с 36 630 до
  37 760 строк. Числа выше относятся к 13:33 UTC и к строке, которую прибор печатает
  вместе с датой запуска. Это не оговорка: подложка **и есть** то, что проход без сети
  измеряет, и её подвижность — свойство предмета, а не прибора.
- **878 `no_version` у `postgrespro`** записаны прогоном 13:02–13:27 UTC, то есть **после**
  A/B (`ru-pg-dbms-902c0b71c419`, 22.11 19:17). Поэтому их нет в журнале A/B — это не
  противоречие, а разные моменты.
- **Пространство проверяется без SSRF.** `validate_url` — гейт **фетча**, а не определение
  пространства, и адрес, не прошедший его, в `url_state` не попадал. Цена вопроса
  измерена: с `validate_url` прибор шёл **10 минут** на 37 760 URL, без него — **10 с**.
- **Прибор не решает, что «правильно».** `outside_space` — утверждение о пакете, а не о
  сайте: если корень вернут в `corpus_urls.yaml`, тот же URL перестанет быть
  `outside_space` без единой правки прибора.
