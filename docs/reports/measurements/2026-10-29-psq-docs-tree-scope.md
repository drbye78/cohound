# Корни Pangolin: где лежит документация и почему профиль расщеплён по пути

**Дата замера:** 2026-10-29, 15:40–15:50 MSK. **Дерево:** рабочее (после `2d1ab73`).
**Сырьё:** `probe.json` рядом с этим файлом — один прогон пробера, числа ниже взяты из него.
**Предмет:** объявленный scope продукта `pangolin` и оси профиля домена для хоста
`platformv.sbertech.ru`.

## 1. Находка живого прогона: дерево документации было вне scope

Прогон `ru-pg-dbms-3d3dc7c3c969` дал у `pangolin` **161 отказ `redirect_out_of_scope`**, и
все 161 ведут на один хост — `platformv.sbertech.ru`, в пути
`/docs/public/PSQ/<версия>/...`. Это не «сайт недоступен» и не ошибка краула: `pangolin.sbertech.ru`
отдаёт редирект на реальную документацию, а объявленный корень того же хоста был
маркетинговым путём `/products/rabota-s-dannymi/pangolin/`. Path-prefix корня документацию
не накрывал, и краул корректно отказался тратить бюджет чужого корня.

Распределение целей по версиям (161 отказ): 8.3.0 — 14, 6.6.1 — 28, 6.6.0 — 27, 7.1.0 — 25,
6.6.5 — 18, 6.5.2 — 14, 6.5.0 — 7, 6.4.2-cve3 — 5, 6.4.2-cve5 — 3, 6.4.0 — 2, 6.7.0 — 2,
6.4.2-cve0 — 2, 6.4.2-cve1/2/4 — по 1, 6.4.3 — 1, 8.1.0 — 1, 8.1.0-соседний `OPM/5.1.20` — 1,
`404.html` — 7. То есть ссылки ведут в **18 разных версий** документации.

## 2. Объявленная редакция — 8.1, а не 8.3

`passports/pangolin/2026-10-01.yaml` объявляет `version: "Pangolin 8.1 (31.05.2026, ядро
11.1.0, Patroni 4.1.0)"`. Свидетельство из документации другой редакции не подтверждает
утверждение об объявленной (precision-first), поэтому корнем объявлена **`PSQ/8.1.0/`**, а
не текущая 8.3.0. Смена редакции — правка паспорта, а не корня.

Родитель `/docs/public/PSQ/` корнем **не** объявлен: его префикс накрывает все 18 версий,
бюджет корня делился бы между ними, а содержимое версий дублируется — платили бы за
дубликаты до дедупа по `content_hash` (замер дубликатов: `2026-10-29-crawl-url-duplication.md`).

## 3. Размер дерева (бюджет ставится по замеру)

15 разделов `common/documents/<sec>/index.html`, сумма ссылок — **1299 страниц**
(нижняя граница: выборочная проверка страниц добавляет перекрёстные ссылки):

| раздел | страниц | раздел | страниц |
|---|---|---|---|
| architecture-components | 254 | programming-guide | 222 |
| reference-guide-sql | 206 | administration-guide | 113 |
| extensions | 127 | reference-guide-postgresql | 123 |
| description-of-functionality | 99 | reference-guide | 50 |
| installation-guide | 44 | glossary | 17 |
| about | 12 | instructions-and-notes | 12 |
| developer-guide | 10 | what-is-new | 6 |
| distribution-kit | 4 | | |

Прежний профиль объявлял `max_documents: 300` на весь хост — втрое ниже уже измеренного.
Потолок ниже измерения объявляет продукт `truncated: max_documents` и снимает все его `❌`
(ложная аномалия I2/I2b), поэтому для docs-корня стоит **2000** — выше измеренного; точное
число даёт следующий прогон, а не этот файл.

Sitemap как источник размера **не годится**: host-wide `sitemap.xml` отдаёт 200 и содержит
**816 `<loc>`**, из них под `/docs/public/PSQ/` — **ноль**. Дерево документации в карту не
входит, поэтому sitemap на docs-ключе был бы no-op плюс запись об отказе на каждом прогоне.

## 4. Оси хоста не однородны по пути (антибот — свойство пути, не хоста)

| URL | обычный HTTP |
|---|---|
| `/docs/public/PSQ/8.1.0/` | **200** |
| `/docs/public/PSQ/8.1.0/common/` | **200** |
| `/docs/public/PSQ/8.1.0/common/documents/about/index.html` | **200** |
| `/products/rabota-s-dannymi/pangolin/` | **401** (антибот) |
| `pangolin.sbertech.ru/` | **401** (антибот) |

Отсюда правка профиля: ключ `host[/path]` поддерживается резолвом
(`core/pipeline/fetch_plan.py:71-109`, побеждает самый длинный `path_key`), поэтому хост
расщеплён на два ключа — `platformv.sbertech.ru` (`browser` + `honest`, бюджет 300) и
`platformv.sbertech.ru/docs/public/PSQ` (`http`, бюджет 2000). До замера стоял один
host-ключ с `browser`, и статическое дерево из 1299 страниц платило цену браузерного рендера.

## 5. Что это меняет в измерении

`crawl_config_digest` считается по разрешённым `CrawlLimits` **на каждый site key**
(`core/pipeline/report.py:636-682`), поэтому правка бюджета и появление нового ключа — это
`execution_change` (§13), то есть **новый `run_id`**: `ru-pg-dbms-7f9a23e3bcf9`
(проверено `hound plan`; прежний прогон `ru-pg-dbms-3d3dc7c3c969` не затронут — профили
читаются на старте процесса).

Сканирование новых корней **отложено до следующего прогона** (решение владельца 29.10.2026):
текущий прогон идёт со старым `url_map` и старым профилем, и подменять ему корпус на ходу
значило бы измерить два корпуса под одним `run_id`.

## 6. Что осталось не объявленным

- 18 версий документации: объявлена одна (8.1.0, редакция паспорта). Остальные 17 —
  доступны, но каждая стоит ~1300 страниц при почти дублирующемся содержимом.
- `platformv.sbertech.ru/docs/public/OPM/5.1.20` — 1 отказ, другая продуктовая линейка
  документации; не объявлено.
- `platformv.sbertech.ru/docs/public/404.html` — 7 отказов, это не документ, а страница
  ошибки; объявлять нечего.
