# Перепись «пустых» чанков корпуса (O40), 27.11.2026

Срез дерева: `ccede80`. Прогон: `ru-pg-dbms-902c0b71c419` (стенд
`~/.cohound/stands/ru-pg-dbms`), `cohound.db` прогона, **270 045** чанков,
23 827 документов.

## Что мерили и чем

Класс O40 («чанк без текста») был назван 14.11.2026 на корпусе `145ad66ca3f9`
(**1 547** чанков, 0.61 %) и с тех пор не пере-мерился: корпус сменился дважды
(`policy-6`, 270 045 чанков; добавлен `gaussdb` — 50 814 чанков из 270 045).
Перепись — прямым запросом к БД прогона, без прибора: класс определяется **регуляркой по
тексту**, а не журналом, поэтому воспроизводится одной командой:

```python
import sqlite3, re, collections, os
db = os.path.expanduser('~') + '/.cohound/stands/ru-pg-dbms/runs/ru-pg-dbms-902c0b71c419/cohound.db'
conn = sqlite3.connect(f"file:{db}?mode=ro", uri=True)
img = re.compile(r'<!--\s*image\s*-->')
tot = 0
img_only, ws_only, tbl_only = (collections.Counter() for _ in range(3))
for pid, text in conn.execute("select product_id, text from corpus_chunks"):
    tot += 1
    noimg = img.sub('', text)
    if noimg != text and not re.sub(r'[|\-:\s]+', '', noimg):
        img_only[pid] += 1
    elif not text.strip():
        ws_only[pid] += 1
    elif not re.sub(r'[|\-:\s]+', '', text):
        tbl_only[pid] += 1
```

## Что это меняет в постановке O40

1. **Прежний класс почти исчез.** Маркеры изображений давали 1 547 чанков на 253 306
   (0.61 %), теперь 57 на 270 045 (0.021 %) — почти в 30 раз меньше по доле. Причина не в
   правке, а в составе корпуса: 1 546 из тех 1 547 были `postgrespro`, а объявленное
   пространство `postgrespro` сужено 24.11 до `/docs/enterprise/18` + сателлиты.
2. **Появился другой, более крупный класс, и он не про картинки.** 2 306 чанков — это
   **пустые строки markdown-таблиц** (`| | | |`), и 2 282 из них — `gaussdb` (корпус из
   `.md` вендорского индекса). Сосредоточены они в пяти документах: 265, 264, 187, 141, 67
   чанков (924 из 2 282). Пример — документ `gaussdb:028c144d…` (628 чанков, 265 пустых):
   пустые идут **через один** (`chunk_no` 70, 72, 74, …), то есть между строками данных.
3. **Значит адрес работы — не чистка индекса.** Пустая строка таблицы не является
   свидетельством, и вычистить её на сборке чанков можно (это `execution_change` с
   переиндексацией), но вопрос «почему строка без содержимого становится отдельным
   чанком» адресован **чанкеру**, а не индексу: правка чанкера убирает и мусор, и повод
   для будущего мусора, а чистка индекса — только следствие. Цена обеих правок не измерена
   (обе меняют состав индекса).

## Границы

- Один снимок подложки, один прогон. Доля junk-чанков — свойство **этого** корпуса;
  `gaussdb` в нём 50 814 чанков из 270 045 (18.8 %), и его вклад в класс непропорционален.
- Регулярка определяет «текст» как «есть символ вне `|`, `-`, `:`, пробельных». Строка
  `---` (горизонтальная черта) этим правилом считается каркасом, хотя она законна как
  разделитель; на этом корпусе таких чанков без других символов — единицы, но правило
  узкое именно так, как записано в приёмке O40.
- Перепись **не** отвечает, пуста ли таблица в источнике: она отвечает только, что в
  чанке нет текста. Для `gaussdb` это `.md` вендора, и пустые строки там, судя по
  чередованию, — артефакт представления таблицы, но это гипотеза, а не замер.
