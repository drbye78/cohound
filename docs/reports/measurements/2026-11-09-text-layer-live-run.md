# `text_layer` живьём: цена механизма и дефект, который эту цену прятал

**Дата замера: 09.11.2026.** План 26 O35. Стенд `~/.cohound/stands/ru-pg-dbms`,
прогон `ru-pg-dbms-48bf65507223`, один продукт (`postgrespro`), `--until corpus`.

## 1. Что запускалось

```bash
COHOUND_HOME=/home/roger/.cohound/stands/ru-pg-dbms \
COHOUND_PATHS_FILE=/home/roger/.cohound/stands/ru-pg-dbms/paths.yaml \
.venv/bin/python -m core.cli run \
  --run-yaml packages/ru-pg-dbms/run.yaml --package packages/ru-pg-dbms \
  --urls packages/ru-pg-dbms/sources/corpus_urls.yaml \
  --only-product postgrespro --pdf-pipeline text_layer \
  --refresh frozen --frozen-source bytes --until corpus --reset --json
```

Почему `frozen`: механизм надо было прогнать на **тех же байтах**, что читал docling, иначе
разница в тексте смешала бы «другой читатель» с «другой корпус». `frozen` берёт
`corpus_raw` по hash и не ходит в сеть. Цена выбора названа в §5: такой проход не
наблюдает, поэтому `complete=false` и `❌` по нему не публикуется (I2d).

Exit `0`, 627 записей в `errors` (разбор — §3). Время: фаза `corpus` **2 169.5 с**, из них
эмбеддинг **1 995.6 с** (92 %), сборка партиции 32.0 с, нарезка 17.8 с
(`metrics.json:resources.stage_timings`).

## 2. Дефект, найденный первым прогоном: «сменился читатель» читалось как «поехал текст»

Первый прогон (та же команда, тот же `run_id`) выбросил **153 документа** из корпуса с
токеном `frozen_reextract_mismatch` — «тот же файл, другой текст». Это неверно:
`pdf_pipeline` объявлен входом прогона (`extractor_stack` → `run_id`), поэтому текст
расходится **по построению**, а не «поехал». Код сравнивал только `content_hash` и не
смотрел, чей штамп у записанной версии.

| | первый прогон | второй прогон (после правки) |
|---|---:|---:|
| `errors` всего | 627 | 627 |
| `frozen_reextract_mismatch` (документ **выброшен**) | **153** | 0 |
| `reextract_engine_changed` (документ **опубликован**, факт назван) | 0 | **153** |
| `frozen` (нет активной версии) | 436 | 436 |
| `frozen_container_empty` | 35 | 35 |
| `extract_failed` | 2 | 2 |
| прочее | 1 | 1 |

Число записей **не изменилось** — изменился их смысл: 153 документа переехали из «выброшен»
в «опубликован, причина названа». Все 153 — standalone PDF (ни один не член контейнера). Из них
в корпусе оказались **87 документов / 16 327 страниц**; остальные 66 — дубли текста: хеш
пере-извлечения каждого совпадает с документом, уже вошедшим в корпус под каноническим
`min(url)` (44 — `postgrespro.ru` `media/…` против `dmedia/…`, 22 — `edu.postgrespro.ru`),
поэтому новых документов они не добавляют.

Правка (`core/pipeline/corpus_ingest.py`): дрейф — это «тот же штамп, другой текст»;
другой штамп — объявленное пере-извлечение с отдельным токеном `reextract_engine_changed`.
Неизвестный штамп (пустая строка) остаётся прежним путём: отсутствие факта не даёт права
объявить пере-извлечение объявленным (A3). Регрессии:
`tests/pipeline/test_corpus_frozen.py::test_frozen_declared_engine_change_keeps_the_document`,
`tests/pipeline/test_corpus_reuse_rebuild.py::test_declared_engine_change_is_named_and_the_document_stays`.

Артефакт сравнения — `2026-11-09-text-layer-live-run/errors.json`: обе стороны
(`before_fix`/`after_fix`), счётчики по токену и все 153 документа (URL + хеш
пере-извлечения). Снят из полных `--json` обоих прогонов разбором по токену после первого
`: `; полные файлы (467 KB и 440 KB) в репозиторий не кладутся — в них тот же материал плюс
436 строк `frozen`, не относящихся к дефекту.

## 3. Агрегат O26: сколько страниц теряет текстовый слой

Счётчик `pages_without_text_layer` (O26) считается только по документам, чья
`partial_reason` несёт машинный токен:

| | значение |
|---|---:|
| PDF-документов в корпусе | 1 715 |
| страниц в них | 53 501 |
| документов с ≥1 страницей без слоя | **254** (14.8 % PDF) |
| страниц без слоя | **459** (0.86 % страниц) |
| документов без слоя целиком (`no_text_layer`) | **0** |

Сверка с независимым прибором: O31 (`2026-11-09-pdf-corpus-profile.md`) на **docling**-корпусе
дал 460 из 53 689 (0.86 %) и 255 документов. Совпадение по доле до второго знака, расхождение
в один документ и одну страницу — разные составы корпуса (1 715 против 1 721 PDF), а не разные
приборы. То есть пустой лист — свойство **PDF**, а не механизма: и docling, и pdfium его видят.

## 4. Цена механизма: −8.50 % символов, страницы совпадают

Сравнение на **общих** документах (1 678 из 1 712/1 715):

| | docling `layout_tables` | pdfium `text_layer` | разница |
|---|---:|---:|---|
| документов | 1 712 | 1 715 | +3 |
| страниц (все) | 53 508 | 53 501 | −7 |
| символов (все) | 73 915 499 | 67 646 395 | **−6 269 104 (−8.48 %)** |
| символов (общие 1 678) | 73 414 056 | 67 172 354 | **−6 241 702 (−8.50 %)** |
| `page_count` расходится | — | **0 документов** | — |
| одинаковый `content_hash` | — | **0 из 1 678** | — |
| `partial` | 0 | 254 | +254 |

Три вывода, каждый с последствием:

1. **−8.50 % символов** — это цена «без таблиц и без моделей», и она того же порядка, что
   независимая потеря идентификаторов O34 (10.0 % на одной книге). Направление согласовано:
   pdfium не теряет текст, он теряет **структуру**, из которой текст собирается.
2. **`page_count` механизм-инвариантен**: 0 расхождений на 1 678 документах. Это делает
   `page_count` годным ключом для `measured_max_pages` (24 §2.2) и для O31 — число страниц
   не зависит от того, кто читал.
3. **`content_hash` не совпал ни у одного документа** (0 из 1 678). Это и есть причина, по
   которой дефект §2 был неизбежен без правки: при смене механизма текст другой **всегда**,
   поэтому «тот же файл, другой текст» не может служить признаком дрейфа.

## 5. Чего этот прогон не измерил, и почему это не недоделка

- **Изменение покрытия** (приёмка O35) — не измерено. `frozen` **не наблюдает**:
  `observed_at`/`capture_id` не пишутся, `corpus_coverage.complete=false` у всех четырёх
  корней, датированный носитель `❌` не публикуется (I2d). Плюс прогон остановлен на
  `--until corpus`, то есть оценки ячеек нет вовсе. Число «сколько `❌` изменилось бы»
  требует живого прохода с сетью и фазы `evaluate` (905 ячеек ≈ 63 мин, замер 08.11).
- **Качество текста** — не измерено и не измеряется суммой символов: минус 8.50 % может быть
  потерей таблиц (ожидаемо) и потерей содержимого (дефект). Это предмет O34 (идентификаторы,
  измерено) и O38 (эталон извлечения).
- **Цена OCR одной страницы** и «можно ли отдать одну страницу в docling, сохранив номер»
  (второй вопрос O35) — не сняты: GPU/память узла были заняты этим же прогоном. Остаются
  открытыми и входят в D6.

## 6. Второй факт того же прогона, к O35 не относящийся

`corpus_coverage.policy_matched = false` на 4 из 4 корней. Причина найдена вычислением и
описана в плане 26 §20.4: `--only-product` сужает материал решений политики до нуля
(`resolve_crawl_policy` строит решения только по корням, у которых есть запись), а не
«сменился механизм». Прибор — `scripts/measure_crawl_space_digest.py`; полная когорта
воспроизводит отпечаток снятия `4badc0e1ed6f976793dbb764` до последнего знака.

## 7. Границы прибора

Один продукт (`postgrespro`), один корпус, `frozen` — без сети и без наблюдений. Символы
сравнивались суммой по документу (`corpus_docs.extracted_chars`), не по страницам: постраничный
текст ни один из механизмов в БД не пишет. Время — стенд 6.9 GiB, 12 threads, RTX 3050 4 GB,
`pdf_device: cpu` (в `run.yaml` стенда).
