## 3. Дефект прибора, найденный на этом же замере

Первая версия пробы дала **`live` 102 из 102** — то есть «ни один адрес не переехал».
Причина: `urllib.request.urlopen` **сам** проходит 301/302, возвращает `200` с конечного
адреса, и класс `moved` становится недостижимым по построению. Это тот же класс отказа, что
«гейт якорей видит только непустую строку»: прибор отвечает «всё хорошо», потому что не
смотрит на предмет. Исправлено обработчиком, который отказывается идти по редиректу
(`_NoRedirect`), после чего `moved` стал виден — и именно он вынес две строки из §2.

Отдельно: `unreachable` в замере 09.11 для `jatoba.ru/Программа-ТП-2023.pdf` был **сбоем
пробы**, а не мёртвым адресом (сегодня `206`, и в корпусе документ есть). Поэтому
`unreachable` в листе — повод для повторной пробы, а не решение; прибор печатает такие
адреса отдельным списком в `stderr`.

## 4. Границы

- Один запрос на адрес, без ретраев: медленный ответ классифицируется как `unreachable`
  («не дождались»), и это **не** «страницы нет».
- Живость не утверждает релевантность: `live` значит «адрес отвечает», а не «это тот
  документ, который процитирован».
- Замер — снимок 15.11.2026; через неделю он снова станет гипотезой, и пере-замер стоит
  одной команды (см. шапку прибора).
