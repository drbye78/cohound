# Markdown-чанкер: план перехода на AST (L0–L4b)

**Тип:** план. **Владелец:** Roger. **Начало:** 03.11.2026, срез `20dbae1` + правки D2.
**Отслеживание:** чеклист слоёв ниже; статус каждого пункта — по факту кода, а не по
обещанию. Правило маркеров — как в `README.md` этого каталога (✅ / ⬜ / ➖ / ❔).

## 1. Зачем

До L1b-1 чанкер markdown (`core/adapters/chunker_markdown.py`) был **строчным конечным
автоматом на регулярках** (`md-heading-4`). Ниже — замеры этого состояния; с L1b-1
(`md-heading-5`) нарезка идёт по AST, и числа «до/после» лежат в
`docs/reports/measurements/2026-11-03-md-chunking-policy.md`. Он знает ATX, fence, setext,
тематический разрыв и YAML-front-matter; всё остальное для него — «строки текста»:
таблицы (кроме случайного предпочтения перевода строки), вложенные списки, blockquote,
indented code, HTML-блоки, сноски, fenced div, line blocks, grid/multiline/simple
таблицы, citation, bracketed span. Следствия измерены или видны из кода:

- **Обрыв фразы на CJK**: абзац без пробелов и переводов строк режется ровно на
  `chunk_size` посреди предложения (замер 03.11 на 2000 иероглифов: чанк кончился
  «…会失败并且», следующий начался «需要回滚。»).
- **Шумность эвристик**: строчный regex «indented code» насчитал 412 документов (25.8 %),
  настоящий парсер нашёл 64 блока `code_block` — ошибка в шесть раз, молча.
- **Таблицы теряют шапку**: 292 из 1450 таблиц когорты длиннее `chunk_size`; шапка
  остаётся в предыдущем чанке, строки без имён параметров нечитаемы как evidence.
- **`context_prefix` — дубль `heading_path`** (`chunker_markdown.py:231`), а промпт печатает
  только один из двух (`core/pipeline/prompt.py:309`): ёмкость поля простаивает.
- **Провенанс не доходит до оценщика**: `RetrievedChunk` не несёт `context_prefix`
  (`core/ports/vector_index.py:34`).

Задача: профессиональный разбор markdown (CommonMark 0.31.2 + GFM + Pandoc markdown) и
нарезка **по структуре**, а не по строкам, с поддержкой RU/EN/ZH.

## 2. Границы

**В области:** CommonMark 0.31.2 (11 блочных и 13 инлайновых правил), GFM (таблицы,
зачёркивание, autolink, task lists, tagfilter), Pandoc markdown (полный список расширений
из §4), многоязычная геометрия (скрипт-зависимые границы, бюджет в токенах), семейство
`text` (`.txt/.log/.sql/.rst`), структурный провенанс до оценщика.

**Вне области (явно):** AsciiDoc, RST-директивы (RST остаётся plain text **до** отдельного
решения, `core/util/document_formats.py:140`), MyST, MDX/JSX-исполнение, Hugo/Jekyll
shortcodes. Это не «никогда»: нет грамматики — нет приёмки — нет кода.

## 3. Инварианты

| | инвариант |
|---|---|
| **P1** | Конкатенация `text` всех чанков + явно исключённые блоки (front matter, reference definitions) **==** входной текст байт-в-байт. Каждый исключённый блок записан в метаданные |
| **P2** | Граница чанка не попадает внутрь **объявленной минимальной единицы** конструкции (строка таблицы, элемент списка, строка кода, инлайновый токен) |
| **P3** | Разрез не попадает внутрь `code span`, ссылки/изображения, inline-html, math, `footnote_ref`, `citation`, `bracketed_span` |
| **P4** | Каждый `chunk.text` — точная подстрока входа (I22 не ослабевает) |
| **P5** | Детерминизм: одинаковые границы в двух прогонах и в двух процессах |
| **P6** | Сдвиг: префикс, оканчивающийся пустой строкой, не меняет границы (кроме `heading_path`) |
| **P7** | Монотонность: рост бюджета не увеличивает число чанков — **проверяемое свойство**, не инвариант: снап по границам предложений может его нарушить, нарушение обязано быть объяснено |
| **P8** | Чанк не начинается с закрывающей пунктуации/закрывающего маркера контейнера |
| **P9** | Чанк, начавшийся внутри таблицы, несёт шапку и выравнивание в `context_prefix` |
| **P10** | Чанк-продолжение fence несёт полный info string |
| **P11** | `heading_path` строится по токенам заголовков; атрибуты (`{#id .cls}`) в путь не входят и пишутся отдельно |
| **P12** | Неизвестная конструкция даёт видимый счётчик `unknown_construct`, а не тихое «плоский текст» |
| **P13** | Покрытие строк: каждая непустая строка входит ровно в один спан верхнего уровня; разрыв = `unknown_construct` |

**Единственный допустимый компромисс:** конструкция больше бюджета режется — только по
внутренним структурным границам, с заголовком-продолжением в `context_prefix` и флагом
`continued`. Всё, что меньше бюджета, обязано быть неделимым.

## 4. Покрытие грамматик

| грамматика | покрытие | чем |
|---|---|---|
| CommonMark 0.31.2 | полное | `markdown-it-py` 4.2.0 (MIT, `mdurl` — единственный транзитивный) |
| GFM | полное | ядро (`table`, `strikethrough`) + `gfm_autolink`, `tasklists` |
| Pandoc: definition lists, footnotes, YAML front matter, header/inline attributes, div-контейнеры, subscript/superscript, math | плагинами | `deflist`, `footnote`, `front_matter`, `attrs`, `container`/`colon_fence`, `subscript`, `superscript`, `dollarmath` (**только** в профиле `pandoc`) |
| Pandoc: grid/multiline/simple tables, table captions, line blocks, example lists, fancy lists/`startnum`, bracketed spans, citations, inline notes, TOML metadata, `raw_tex`/`latex_macros`, implicit figures, emoji, `mmd_header_identifiers` | **свои правила** | `core/adapters/md_dialect/` — каждое правило обязано выставлять `token.map` |
| Семантика разбора блоков Pandoc (`blank_before_header`, `blank_before_blockquote`, `lists_without_preceding_blankline`, `fancy_lists`, `four_space_rule`) | **своя** | порядок правил объявлен явно (precedence), покрыт тестами |

**Профиль диалекта — свойство источника, а не прогона.** `trafilatura` (HTML) и `docling`
(PDF/Office) не пишут Pandoc-разметку; включать им `dollarmath` нельзя — `$$` в
документации PostgreSQL это **dollar-quoting SQL** (838 вхождений в 91 документе когорты),
а не формула. Профиль входит в `chunker_version`.

## 5. Политика нарезки по конструкциям

| конструкция | минимальная единица | резать внутри | `context_prefix` продолжения | метаданные |
|---|---|---|---|---|
| ATX / setext | блок | нет | — | `heading_path`, `attrs` |
| параграф | блок; при переполнении — безопасные позиции (P3), затем границы предложений | да | — | — |
| fence / indented code | блок | при переполнении — по строкам | fence + info string | `fence_info`, `lang` |
| raw block (HTML/LaTeX) | блок | при переполнении — по строкам | маркер raw | `raw_format` |
| pipe table | строка | только между строками | шапка + `\|---\|` + выравнивание | `table_header`, `align` |
| grid / multiline / simple table | строка | только между строками | шапка в pipe-виде | `table_header`, `caption` |
| table caption | вместе с таблицей | нет | — | `caption` |
| список / task list | элемент `li` (вложенные — с родителем) | между элементами | маркер и отступ предка, `start` | `list_depth`, `start`, `task_state` |
| definition list | терм + его определения | между парами | терм | `dl_term` |
| blockquote / fenced div | контейнер | между дочерними блоками | `> ` / `::: {.cls}` | `containers`, `attrs` |
| line block | строка | между строками | `\| ` | — |
| footnote definition | вся дефиниция | нет | id | `footnote_def` |
| math block | блок | **нет** | `$$` | `math` |
| YAML/TOML metadata, reference definition | блок | нет | — | `front_matter` / `ref_def` (в `text` не входят) |
| figure (`![..]` один в абзаце) | параграф | нет | — | `figure` |
| citation / footnote ref / bracketed span | инлайновый токен | нет | — | `citations`, `footnote_refs`, `spans` |

**Перекрытия не будет.** `chunk_overlap` (сейчас 200) несовместим с P1: он дублирует
абзацы и шапки таблиц, а докстринг уже фиксирует, что дубли удваивают evidence-шум. Снятие
перекрытия — отдельный замер «до/после» в L0.

## 6. Слои работ

### L0 — замеры и решения (до кода)

- ✅ `\r`-only окончания строк **уничтожаются** в `core/util/sanitize.py:353`
  (`strip_control_chars`): `'a\rb'` → `'ab'` — CR-only markdown теряет всю строчную
  структуру до чанкера. Решение: нормализовать `\r\n|\r` → `\n` до удаления управляющих
  символов, `finalize-1` → `finalize-2` (меняет `content_hash` ⇒ `execution_change`).
- ✅ BOM **сохраняется** (`'\ufeff# h'`): первый заголовок документа с BOM не распознаётся.
  Решение: снимать BOM в финализации (та же версионная граница).
- ✅ Табы сохраняются ⇒ парсер обязан раскрывать их по 4-колоночным стопам (CommonMark).
- ✅ Перекрытие против P1 (см. §5) — снять, замерить.
- ✅ Замер цены `heading_path`/`context_prefix` в промпте сделан: промпт-вход p50 324 /
  p99 800 / max 2 398 токенов, контекст добавляет +44 токена к медиане (+15.7 %);
  потолок **не вводится** — доля «контекст > 25 % текста» оказалась короткими секциями,
  а хвост — дефектом извлечения (`2026-11-03-md-chunk-geometry-tokens.md`, §L4).
- ✅ `semantic-text-splitter`: **снят**. Он не зависимость и не установлен; границы
  предложений делает `core/util/text_utils.py` (`SENTENCE_END_CHARS`, `is_cut_boundary`,
  `sentence_terminated`), общий для обоих чанкеров. Остаток обрывов на корпусе — 43 из 606
  границ (7.1 %); снизит ли его более умный детектор предложений (сокращения, инициалы),
  **не измерено**, и это отдельная работа, а не пункт этого плана.
- ✅ Решения по разметке приняты **по грамматике, а не по вкусу**: `##标题` (ATX без
  пробела) — по CommonMark/GFM **не заголовок**, расширение не вводим, пока нет корпуса,
  где это стоит потерянных заголовков; CJK-маркеры списков (`1、`, `（1）`, `1．`) — не
  маркеры markdown, остаются текстом; полноширинные формы учитываются **в границах**
  (`。！？；`, клаузы `，、：`, `CLOSING_CHARS`) и текст никогда не нормализуется;
  суффиксы `.mdx`/`.mdc`/`.qmd`/`.rmd` добавлены, `.adoc` — отказ, `.rst` — plain text
  (L1c).

### L1b — перевод markdown-чанкера на AST (execution_change)

Разбит на два инкремента: первый даёт качество без изменения схемы, второй — провенанс.

**L1b-2 — провенанс и контракт (схема)**

**L1b-2b — колонки (схема; отдельный инкремент)**

- ✅ **2b-1: смещения куска.** `corpus_chunks.char_start`/`char_end`, `SCHEMA_VERSION`
  3.15.0 → **3.16.0** (DDL без `ALTER`-шимов; старые БД — видимый
  `SchemaVersionMismatch`). `Chunk` несёт `char_start`/`char_end` (поля **в конце**:
  позиционные конструкторы не поехали), markdown-чанкер заполняет их тем же срезом, из
  которого собран `text`. Инвариант — код, а не обещание: пара целиком,
  `0 <= char_start < char_end`, `char_end - char_start == len(text)`
  (`CorpusChunk`, `tests/selfcheck.py::_corpus_chunk_span`). Приёмка **проводки** —
  `tests/pipeline/test_corpus_chunk_offsets.py` (читает строки `corpus_chunks` и сверяет
  `doc_text[start:end] == text`); покрытие и монотонность — `test_chunker_markdown.py`.
  Метрика **P14** харнесса («смещения ≠ срез чанка») слабее, чем звучит: `text` куска
  определён как срез, поэтому она ловит рассогласование полей, а не неверную позицию
  (проверено мутациями: зубы — у теста, а не у метрики).
- ✅ Побочно вскрыт **дефект хранения**: `CorpusChunk` наследовал
  `str_strip_whitespace=True`, а `content_hash` считается по необрезанному срезу — то есть
  `corpus_chunks.text` не совпадал с текстом, по которому посчитан его хеш (355 из 400
  чанков кончаются `\n\n`, потому что P1 требует сохранять границу). Теперь текст
  хранится байт-в-байт (`ConfigDict(extra="forbid", str_strip_whitespace=False)`), и хеш
  сходится с хранимым текстом.
- ✅ **2b-1, доводка проводки (найдено гейтом).** Поля были объявлены, но до БД на
  штатном пути не доезжали: кандидат ингеста был 5-кортежем, `_accept_chunk_candidates`
  строил `CorpusChunk` без смещений, а `chunk_meta` не имела под них колонок — то есть
  документ, переиспользованный из chunk-set, получил бы `NULL` при любом тексте. Теперь:
  кандидат — **7-кортеж** `(chunk_no, text, heading_path, context_prefix, provided_hash,
  char_start, char_end)` по всей цепочке (сборка из `chunk`, гейт I19, `accepted`,
  `write_document_state`); `chunk_meta` получила `char_start`/`char_end`,
  `STATE_SCHEMA_VERSION` **6 → 7** (колонки в `CREATE TABLE`, без `ALTER`; файлы версий
  ≤ 6 отвергаются `SchemaVersionMismatch`); оба reuse-пути (`active_reuse`, offline) и
  adopt-путь читают и пишут смещения как есть, `NULL` читается как `None`, а не `0`.
  `chunker_version` → **`policy-3`**: `str_strip_whitespace=False` меняет хранимый текст,
  вход эмбеддера и байты промпта (`prompt_sha256`), поэтому изменение объявлено новым
  `run_id`. Набор чанков и границы не изменились.
- ⬜ **2b-2: `structure_json`** — ждёт потребителя (parent-child, вне области плана):
  колонка без читателя — заготовка, а не провенанс. Набор чанков она не меняет, поэтому
  отдельный bump дешевле, чем колонка «на будущее».

## 8. Риски и чего план не обещает

1. **Смещения внутри контейнеров.** Инлайновые токены без `map`, `content` без
   `>`-префиксов. Обход — сканер по сырому срезу (L1a); если сканер не покрывает
   конструкцию, разрез откатывается к границам блоков и это видно в счётчиках.
2. **Паритет с Pandoc** — только на testsuite и дифференциальном оракуле. Полного
   паритета без оракула не обещаем.
3. **Атомарность сверх бюджета** невозможна физически; компромисс ограничен §3.
4. **Стоимость**: каждый слой — `execution_change` (новый `run_id`, пере-эмбеддинг;
   пере-краул по смыслу не нужен, но прогон собирает корпус заново).
