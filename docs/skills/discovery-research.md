# Skill: discovery-research (коHound)

Методика внешней разведки для **Discovery-агента** (Ш2, §7.3 регламента) и пополнения
реестров источников. Категорийно-нейтральна: конкретные продукты/вендоры/реестры задаются
данными пакета (`packages/{case_id}/`), а не этой методикой.

**Происхождение:** адаптировано из проекта gtm (`skills/competitor-research/SKILL.md`,
`skills/regulatory-watch/SKILL.md`, `skills/oss-solution-scout/SKILL.md` — собственная
разработка владельца). Доменная специфика удалена,
операционные приёмы разведки сохранены.

## Роль и границы (§7 регламента)

- Discovery — сценарий, где **внешний поиск допустим** (в отличие от оценщика, I18).
- Выход Discovery — **кандидат**, а не доказательство: компонент/роль/связь проходят G2.
- Найденный контент становится evidence **только** после corpus_raw → extract → chunk →
  `content_hash` → index (I19). Ссылка из поиска — кандидат, не доказательство.
- Всё симметрично по когорте: одинаковый протокол и бюджет усилия для всех продуктов (I16, I23).

## Дисциплина доказательности

1. Каждому факту — **URL и дата**; различай **факт** (со ссылкой) и **оценку/гипотезу**
   (помечай явно). Эта дисциплина — операционное отражение инвариантов I2/I2b.
2. **Отсутствие ≠ отсутствие функции.** «Нет» допустимо только при публичном свидетельстве
   явного отсутствия; иначе — «не установлено» (❓). См. §4.2 регламента (absence-правила).
3. Только публичные источники. Без обхода авторизации, платного доступа и антибот-защиты
   (§3.2, §10). Закрытые каналы не трогаем.
4. Ничего не выдумывать: где не уверен — «проверить/уточнить».

## Операционные приёмы разведки

**Мониторинг известных источников (watch-URL).**
- Реестр наблюдаемых URL — данные пакета (`packages/{case_id}/cohort.yaml` /
  `domain_profiles.yaml`), не часть ядра.
- Снимок страницы → diff с предыдущим снимком → дельта (что добавилось/изменилось:
  версии, возможности, сертификаты, цены). Дельта важнее полного описания.

**Публичные Telegram-каналы** — через веб-превью `https://t.me/s/<handle>` (без API и
авторизации). Берём последние посты, диффим со снимком. Закрытые — вне scope.

**Discovery новинок (не пропускать свежее).**
- GitHub Search API по **дате создания**: `created:>прошлый_прогон`, `sort=updated`,
  без порога звёзд (у новинок их мало). Темы — из категории кейса.
- По находке: дата, лицензия, зрелость (prototype/early/usable), в чём новое, релевантность.

**Кросс-язычная разведка.** Ищи на RU и EN; зарубежные лидеры — «барометр» (куда движется
область), а не обязательно член когорты. Для соHound EN-контур обязателен (R10).

## Связь с когортой и матрицей (Ш2 → G2)

- Роль найдена у большинства когорты и не найдена у одного → **прицельный повтор** тем же
  протоколом; итог — `not_found` (❓), **не** ❌ (§5).
- Новую возможность/роль, введённую для одного продукта, доводи до **всех** продуктов
  сравнения — иначе матрица несопоставима.
- Каждый кандидат связи (component × role) обязательно несёт `relationship_evidence`
  (доказательство существования **и** связи в роли), иначе G2 не проходит (precision-first).

## Куда складывать

- Сырьё — `corpus_raw/{product_id}/` (retention), метаданные — `corpus_docs`/`corpus_chunks`.
- Кандидаты ролей/сателлитов — в паспорт продукта (`passports/{product_id}/`), статус `draft`
  до G2.
- Вызовы поиска — в `search_log` (provider, query, language, `termination_reason`) — I23.
