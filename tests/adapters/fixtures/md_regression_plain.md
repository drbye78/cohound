# Чек-лист проверки корректности работы

## Статус работоспособности компонентов сервиса

Для проверки работоспособности сервиса и его компонентов воспользуйтесь командами, приведенными ниже.

### Cервис Recovery Manager

Проверка пользователем работоспособности как отдельных сервисов, так и системы в целом.

#### Последовательность выполнения

Выполните команду `recovery-manager healthcheck services`.

#### Результат

В результате выполнения команды будет выведено сообщение, которое отобразит статус работоспособности сервисов и системы в целом, например:

```
Agent Manager                                [HEALTHY]
Task Manager                                 [HEALTHY]
Storage Manager                              [HEALTHY]
___________________________________________________________________
Overall system                               [HEALTHY]
```
Описание статусов работоспособности и их значения:

| Статус | Обозначение | 
|---|---|
| `HEALTHY` | Компонент функционирует нормально | 
| `UNHEALTHY` | Компонент недоступен | 

### Cервис Copywala

Проверка пользователем работоспособности copywala.

#### Последовательность выполнения

Инициируйте проверку работоспособности через CLI утилиты copywala командой `copywala healthcheck`.

#### Результат

В результате выполнения команды будет выведено сообщение, которое отобразит статус работоспособности утилиты copywala:

```
$ copywala healthcheck
Config                   [OK]
Logging                  [OK]
Target DB                [OK]
PBRA DB                  [OK]
________________________________________
Overall System           [OK]
```
### Cервис PBR-Agent

Проверка пользователем возможности запуска сервиса PBR-Agent и доступности подключения к инфраструктуре CopyWala.

#### Последовательность выполнения

Для проверки работоспособности PBR-Agent воспользуйтесь командой `pbr-agent healthcheck`.

#### Результат

В результате выполнения команды будет выведено сообщение, которое отобразит статус работоспособности компонента PBR-Agent:

```
Log                      [OK]
Config                   [OK]
Agent ID                 [OK: 01956688-fda2-72ce-a4ae-bdc98a951828]
PBRA DB                  [OK]
Agent Manager            [OK]
________________________________________
Overall System           [OK]
```
### Cервис Copywala VDB

Проверка пользователем работоспособности сервиса Copywala VDB.

#### Последовательность выполнения

Инициируйте проверку работоспособности Copywala VDB через CLI компонента Copywala VDB командой `copywala-vdb healthcheck`.

## Справка по команде `copywala-vdb healthcheck`

**Описание**:

Запускает проверку работоспособности утилиты copywala-vdb.

**Синтаксис**:

```
copywala-vdb healthcheck [flags]
```
**Обязательные параметры**:

Нет.

**Опциональные параметры**:

`[flags]` – доступны следующие флаги:

| Флаг | Описание | 
|---|---|
| `-h\|--help` | Показать справку по команде | 
| `-c\|--config <path to copywala-vdb config>` | Использовать конфигурационный файл, отличный от файла по умолчанию: `/etc/pbr/copywala-vdb.yaml` | 

#### Результат

В результате выполнения команды будет выведено сообщение, которое отобразит статус работоспособности компонента Copywala VDB:

```
INF copywala-vdb 1.3.0 (35ab33bc) compiled at 2026-05-04_11:02:27
+--------------+--------+
| CHECK PARAMS | RESULT |
+--------------+--------+
| Config       | OK     |
| Logging      | OK     |
| VectorDB     | OK     |
+--------------+--------+
| ALL          | OK     |
+--------------+--------+
```
### Cервис Copywala OB

Для проверки работоспособности и подключения к OceanBase Database в CLI copywala-ob выполните команду:

```
copywala-ob db info
```
При успешном подключении будет выведена информация об экземпляре БД.

При некорректном подключении в CLI будет выведено сообщение об ошибке:

```
ERR connect to oceanbase db err="<ошибка подключения>"
```
### Cервис Storage Service

Проверка подключения copywala к хранилищам резервных копий.

Подробное описание поддерживаемых типов хранилищ приведено в разделе Хранилища резервных копий.

#### Последовательность выполнения

Инициируйте проверку подключения к хранилищу резервных копий одной из следующих команд в зависимости от типа хранилища:

- для хранилища Local FS: - для хранилища S2: - для хранилища S3: - для хранилища DDBoost: 

#### Результат

В результате выполнения команды будет выведен статус подключения к хранилищам резервных копий и WAL-файлов.

- Local FS
- S2
- S3
- DDBoost

```
+-------------------------+--------+
| PATH                    | RESULT |
+-------------------------+--------+
| /destination/path/      | OK     |
+-------------------------+--------+
| ALL                     | OK     |
+-------------------------+--------+
```
Таблица содержит итоговые результаты проверки:

- Результат проверки доступа к папке с резервными копиями и WAL-файлами в локальном хранилище. Если ОК, папка доступна.
- Итоговый результат проверки всех путей (ALL) также положителен - все папки по указанным путям доступны.

```
+----------+---------------------+--------------+------------------+--------+
| PROTOCOL | HOST                | STORAGE PATH | DATA DOMAIN HOST | RESULT |
+----------+---------------------+--------------+------------------+--------+
| tcp      | tcp-host:tcp-port   |              |                  | OK     |
| grpc     | grpc-host:grpc-port |              |                  | OK     |
+----------+---------------------+--------------+------------------+--------+
| ALL      |                     |              |                  | OK     |
+----------+---------------------+--------------+------------------+--------+
```
Таблица содержит результаты проверки доступности storage-service, указанного в `copywala.yaml`. Если в `copywala.yaml` указано несколько storage-service, выводится сообщение об ошибке.

- TCP и GRPC-соединения по указанным IP-адресам работают корректно (OK).
- Итоговый результат всех проверок (ALL) — ОК, что свидетельствует о том, что все указанные соединения работают корректно.

```
+---------------------------------------------+--------+
| URI                                         | RESULT |
+---------------------------------------------+--------+
| http://host:port/bucket                     | OK     |
+---------------------------------------------+--------+
| ALL                                         | OK     |
+---------------------------------------------+--------+
```
Таблица содержит результаты проверки доступности хранилища S3, указанного в `copywala.yaml`.

- Проверка доступности бакета в хранилище s3. Если ОК, бакет доступен.
- Итоговый результат проверки всех ресурсов — также OK, подтверждающий, что никаких ошибок обнаружено не было.

```
+--------------------------+--------+
| URI                      | RESULT |
+--------------------------+--------+
| ddboost://server1.domain | OK     |
+--------------------------+--------+
| All                      | OK     |
+--------------------------+--------+
```
Таблица содержит результаты проверки доступности хранилища DDBoost, указанного в `copywala.yaml`. Если ОК, хранилище доступно.

### Cервис Agent Manager

Для проверки работоспособности в CLI agent-manager выполните команду:

```
agent-manager self-test
```
В случае успешной проверки работоспособности будет выведено сообщение:

```
INF agent-manager: self-test passed successfully
```
### Cервис Task Manager

Для проверки работоспособности в CLI task-manager выполните команду:

```
task-manager self-test
```
В случае успешной проверки работоспособности будет выведено сообщение:

```
INF task-manager: self-test passed successfully
```
### Cервис Storage Manager

Для проверки работоспособности в CLI storage-manager выполните команду:

```
storage-manager self-test
```
В случае успешной проверки работоспособности будет выведено сообщение:

```
INF storage-manager: self-test passed successfully
```
